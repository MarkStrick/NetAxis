# ภาพหน้าเว็บ NETAXIS สำหรับทำโปรโมท

ยังไม่ได้ถ่าย screenshot จริง เพราะเครื่องมือ browser ของแชตนี้ถูกตั้งค่าปิดการเข้าถึง localhost ต้องใช้ URL ที่เปิดผ่าน Internet หรือเปลี่ยนการตั้งค่าการเข้าถึง localhost ก่อน

## ห้องตัวอย่างที่เตรียมไว้

ไฟล์ `NETAXIS_DEMO_WORKSPACE.json` ใช้แบบสำนักงานที่แบ่ง Users / Servers / Guest มี 10 อุปกรณ์ แผน IPAM และ 4 scenarios ข้อมูลเป็นตัวอย่างจาก Template ของโปรเจกต์ ไม่มี token, recovery key หรือผลตรวจเครือข่ายจริง

นำไฟล์เข้าได้ที่หน้าแรก → กู้คืน Workspace จากไฟล์ → ใส่ชื่อ `NETAXIS Demo` → กู้คืนเป็นห้องใหม่ ระบบจะสร้างห้องอายุ 24 ชั่วโมง เจ้าของยังแก้แผนได้ ส่วนผู้เข้าร่วมถูกตั้งให้ดูอย่างเดียว

## ภาพที่ต้องเก็บ

ชื่อไฟล์ในตารางเป็นชื่อที่เตรียมใช้ ยังไม่มีไฟล์ภาพเหล่านี้

| ชื่อภาพ | หน้าที่ถ่าย | ให้เห็นอะไร | ข้อความสำหรับใช้คู่กับภาพ |
| --- | --- | --- | --- |
| `01-home.png` | หน้าแรก | ชื่อ NETAXIS และภาพรวมหน้าเว็บ | วางแผนเครือข่ายให้เห็นภาพ |
| `02-templates.png` | รายการ Templates | แบบสำเร็จรูป 4 แบบ | เริ่มออกแบบจาก Template ที่พร้อมต่อยอด |
| `03-topology.png` | ห้องตัวอย่าง | แผนผัง Users / Servers / Guest ที่จัดพอดี canvas | ออกแบบและจัดการเครือข่ายในพื้นที่เดียว |
| `04-simulator.png` | Simulator | เลือก `Users → Servers · routed TCP 443` แล้ว Pause ขณะเห็น packet | ทดลองเส้นทางข้อมูลก่อนนำแผนไปใช้ |
| `05-pdu-details.png` | PDU Information | Event List และ OSI / packet details | ดูการเดินทางของแพ็กเก็ตทีละขั้น |
| `06-ip-planning.png` | Calculate / Validate | Subnets, gateway, utilization และผลตรวจแผน | แบ่ง IP และตรวจข้อผิดพลาดได้ในหน้าเดียว |
| `07-what-if.png` | Scale / What-if | ทดลองเพิ่ม Users แล้วแสดงผลก่อน/หลัง | เตรียมแผนสำหรับวันที่เครือข่ายเติบโต |
| `08-live-verify.png` | Live Verify | หน้า Probe และคำอธิบายการตรวจ | เทียบแผนกับเครือข่ายจริงผ่าน Probe |

ภาพ Live Verify ของห้องตัวอย่างจะยังไม่มีผลตรวจ หากไม่มี Probe จริง ให้ถ่ายหน้าตามสถานะที่มีและใช้ข้อความอธิบายฟีเจอร์ ไม่สร้างผลตรวจหรือจำนวนอุปกรณ์ขึ้นมาเอง

## วิธีจัดภาพ

- เก็บต้นฉบับแนวนอนขนาดประมาณ 1920 × 1080 หากเครื่องมือรองรับ และเก็บไฟล์ PNG
- กด Fit ก่อนถ่าย Topology เพื่อให้เห็นอุปกรณ์และสายครบ
- ปิด toast, tooltip และ dialog ที่บังเนื้อหา ยกเว้นภาพที่ต้องการแสดง dialog นั้นโดยตรง
- เลื่อน Event List ให้เห็นเหตุการณ์ที่อ่านง่าย และเลือก event ที่มีรายละเอียดก่อนถ่าย PDU Information
- กันพื้นที่รอบข้อมูลหลักไว้สำหรับครอปเป็นรูปโพสต์ภายหลัง
- ใช้ข้อมูลตัวอย่าง และหลีกเลี่ยงการเผยแพร่ room code, recovery key, Probe token หรือข้อมูลเครือข่ายส่วนตัว

## รูปโปรโมทที่ทำต่อจาก screenshot ได้

1. รูปเปิดตัว: ใช้ Topology เป็นภาพหลัก พร้อมข้อความ “NETAXIS — Plan. Scale. Verify.”
2. รูปรวมฟีเจอร์: ใช้ภาพ Templates, IP Planning และ Simulator พร้อมคำอธิบายสั้น ๆ
3. รูปการเติบโต: ใช้ภาพ What-if พร้อมข้อความ “รู้ก่อนว่าวงเครือข่ายเดิมจะรองรับพอไหม”
4. รูปการตรวจจริง: ใช้หน้า Live Verify พร้อมข้อความ “ตรวจสิ่งที่พบ เทียบกับสิ่งที่วางแผนไว้”

คำว่า Realtime ใน Simulator หมายถึงการเล่นแบบจำลองต่อเนื่อง ส่วนการตรวจอุปกรณ์จริงเป็นหน้าที่ของ Probe จึงควรเขียนข้อความโปรโมทให้สอดคล้องกับภาพที่นำมาใช้
